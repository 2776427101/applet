# 零成本体验版路线

> 目标：让身边的几个人扫码就能用上真实数据，**一分钱不花，不备案、不买域名、不买服务器**。
>
> 适合：自己测试、给同学朋友玩、边用边改。不适合：给不认识的人用、需要 7×24 可用。

---

## 为什么这条路能成立

三件事凑在一起，把成本和门槛都消掉了：

| 平时必须做的 | 为什么这里可以跳过 |
|---|---|
| 买云服务器 | 后端跑在你自己电脑上，手机和电脑同一个 WiFi/热点直连 |
| 买域名 + 备案 | **不提交审核就不需要备案**。体验版只在成员之间流通 |
| 配 HTTPS 证书 | 走**局域网明文 HTTP**，手机上点一次「打开调试」微信就放行 |

代价只有一个：**你的电脑不能关机**。这一条接受了，其余全是零成本。

---

## 整体链路

实测走通的是**局域网 IP 直连**，不经过任何穿透服务：

```text
朋友的手机（微信打开体验版，已点「打开调试」）
        │
        │  http://172.25.39.216:8080/api   明文请求（调试模式下不校验域名）
        ▼
同一个 WiFi / 手机热点          ← 不经过公网，不经过任何第三方
        │
        ▼
你的电脑
  ├─ Spring Boot  :8080      ← 后端（明文 HTTP，本来就不用改，监听 0.0.0.0）
  └─ MySQL        :3306      ← 数据库
```

前提是**手机和电脑在同一网段**。最省事的办法：手机开热点、电脑连热点。
好处是走到哪都能用，也不受学校网络限制（校园网常开客户端隔离，设备之间互相 ping 不通）。

IP 是 DHCP 分的，**热点重连就可能变**（实测从 `10.174.119.216` 变成过 `172.25.39.216`）。
变了就得改 `.env.production` 并重新构建。第 2 步给了工具，专门对付这件事。

### 为什么不用内网穿透

SakuraFrp 这条路线**实测走不通**，三种组合全试过了：

| 组合 | 实测结果 |
|---|---|
| HTTP 隧道，明文 | `501`，被节点网关拦截（响应头里带 `Server: SakuraFrp`） |
| HTTP 隧道 + 自动 HTTPS | `ERR_CERT_AUTHORITY_INVALID`（`errno: 600001`），自签证书微信真机直接拒 |
| **TCP 隧道，明文** | **同样是 `501`** —— 拦明文的是节点，跟隧道类型无关 |

这里要纠正一个很容易搞错的直觉：**TCP 隧道并不等于「绕过网关」**。
节点上的 80/443 入口照样会识别并拦截明文 HTTP。

判断隧道类型也**不能看日志**——HTTP 隧道同样会打印「TCP 隧道启动成功」
（那说的是底层传输协议，不是隧道用途）。唯一可靠的验证方式是发一次真实请求：

```bash
bash scripts/check-tunnel.sh frp-sea.com:23200
```

要给朋友用、又不想让他们连你的热点，**必须换给真证书的穿透方案**。
目前不花钱又能过微信证书校验的只有 cloudflared 的 `trycloudflare.com` 临时域名。

代价：小程序必须在「打开调试」状态下才允许访问明文 HTTP。你和朋友各点一次，一次性成本。

**理解了这张图，后面每一步的位置就清楚了**：第 1 步修好最右边，第 2 步决定怎么连到中间，
第 3–4 步让最左边能连上，第 5–6 步才是给别人用。

### 第 1 步 · 让后端在本机跑起来

**为什么**：先把「代码本身对不对」验证掉。这一步不通，后面全是白费力气。
它和网络、小程序一点关系都没有，是最容易排查的一环。

```bash
cd class-assistant/backend/class_assistant_server

DB_PASSWORD=你的数据库密码 ./mvnw spring-boot:run \
  '-Dspring-boot.run.arguments=--server.port=8080'
```

两个容易踩的点：

- **必须显式传 `--server.port=8080`**。环境里有个 `SERVER__PORT` 变量会被 Spring
  的宽松绑定当成 `server.port`，导致端口变成别的值然后报「已被占用」。
- **第一次跑不要加 `-o`（离线）**。`spring-boot:run` 的运行期依赖没下载过的话离线会失败。
  编译可以离线，启动不行。

看到这行就是成功了：

```
Started ClassAssistantServerApplication in x.xxx seconds
```

验证（另开一个终端）：

```bash
curl -s http://127.0.0.1:8080/api/teacher/home/overview
```

期望返回 `{"code":1002,"message":"未登录"...}`。
**这个「报错」就是成功** —— 说明服务活着、拦截器生效了。

✅ **检查点 1**：curl 返回 `code:1002`。

### 第 2 步 · 让手机能连到你的电脑

**为什么**：你的电脑在局域网后面，手机得先找得到它。

#### 2.0 局域网直连（当前采用，已实测通过）

**直接跳过 2.1–2.3**，那是走不通的旧路线。

1. **手机开热点，电脑连这个热点**
   别用学校 WiFi：校园网常开客户端隔离，同一网段也互相 ping 不通。

2. **确认后端监听所有网卡**
   Spring Boot 默认就是 `0.0.0.0`。检查 `application.yml` 里没有写死 `server.address: 127.0.0.1`。

3. **查本机 IP**
   ```powershell
   Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -notlike '127.*' }
   ```
   真实网卡是 `WLAN`。VMware（`192.168.x.1`）、Radmin VPN（`26.x.x.x`）、
   LetsTAP、还有一堆 `169.254.*` 都会混在结果里，别选错。

4. **放行 8080 端口**（只需一次）
   ```powershell
   netsh advfirewall firewall add rule name="班级助手-8080" dir=in action=allow protocol=TCP localport=8080
   ```
   少这一步，手机浏览器会一直是「无法访问此网站」。用完记得删：
   ```powershell
   netsh advfirewall firewall delete rule name="班级助手-8080"
   ```

5. **写进前端配置**：`.env.production` 的 `VITE_API_BASE_URL`
   ```ini
   VITE_API_BASE_URL=http://172.25.39.216:8080/api
   ```

6. **先验证，再构建**：手机浏览器打开 `http://<你的IP>:8080/api/teacher/home/overview`
   看到 `{"code":1002,"message":"请先登录"}` 就对了。
   **不要跳过这步** —— 浏览器都打不开就去构建小程序，只会白折腾一遍。

> **IP 会变。** 热点重连就可能换一个（实测 `10.174.119.216` → `172.25.39.216`）。
> 变了就重做第 5 步 + 重新构建。用连接测试工具能省点事，见 [`tools/connection-tester`](../tools/connection-tester/README.md)。

✅ **检查点 2 · 局域网**：手机浏览器能看到 `{"code":1002,"message":"请先登录"}`。
这一步过不了，后面构建再多次也没用。

#### 2.1 SakuraFrp 建隧道（已实测不通，仅存记录）

**为什么**：你的电脑在家庭宽带后面，外面的手机根本找不到它。
内网穿透就是给你电脑开一个公网门牌号。

1. 打开 SakuraFrp 启动器（`C:\Program Files\SakuraFrpLauncher`），登录账号
2. 如果提示需要**实名认证**，先去做 —— 国内节点必须实名，免费的
3. 新建隧道，按这个填：

| 字段 | 填什么 |
|---|---|
| 隧道类型 | **TCP**（UDP 绝对不行，见 2.2） |
| 本地 IP | 留空（= 本机 127.0.0.1） |
| 本地端口 | `8080` |
| 远程端口 | 自己填个五位数，别留空 |
| 自动 HTTPS | **启用**（禁用的话明文一律被节点拦成 501） |
| 访问密码 | 留空 |

4. 保存后启动隧道，面板上会显示一个地址，形如 `cn-bj.natfrp.cloud:23456`
   （节点不同域名不同，**以你面板上显示的为准**）

⚠️ 如果下拉里没有 `TCP` 这一项，说明当前节点不支持，换一个节点再建。

⚠️ **这条隧道不要删**。免费隧道只要不删，地址就一直固定；
删了重建地址会变，前端就得重新构建上传。

#### 2.2 关于 HTTPS 的实测结论

**以下三条都是实测出来的，不是推测：**

| 组合 | 实测结果 |
|---|---|
| 任意隧道类型 + 明文 `http://` | ❌ 节点返回 `501 Not Implemented`，**HTTP 隧道和 TCP 隧道都一样** |
| 任意隧道类型 + 「自动 HTTPS」 | ⚠️ 能通，但证书是 frpc 现场生成的**自签证书** |
| 自备域名 + 真证书 | ✅ 唯一确定可行，但要买域名 |

**关键认知：那 501 是 SakuraFrp 节点吐的，不是微信拦的。**

```bash
curl -sI --noproxy '*' http://frp-sea.com:23200/api/teacher/home/overview
```

```
HTTP/1.1 501 Not Implemented
Server: SakuraFrp
```

页面正文写着：

> 您正试图使用 HTTP 协议访问此隧道……请启用 HTTPS 后，使用 HTTPS 访问此隧道

所以微信那边「打开调试」放行 http 也**没用** —— 请求还没出节点就被拦了。
这也是为什么「选 TCP 类型」救不了明文。

**开了自动 HTTPS 之后，证书长这样**：

```bash
openssl s_client -connect frp-sea.com:23200 -servername frp-sea.com </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer
```

```
subject = C=CN, CN=SakuraFrp Automatic TLS sn.763574480
issuer  = C=CN, CN=SakuraFrp Automatic TLS sn.763574480   ← 自己签给自己
```

日志里也印证了：`已为 frp-sea.com 生成自签证书, 保存到 C:\ProgramData\SakuraFrpService\FrpcWorkingDirectory`。

微信官方社区（2025-08-07）的说法是：真机调试会跳过**域名**校验，
但「**真机环境仍会校验 HTTPS 证书有效性，不支持自签名证书**」。
民间也有「开调试能绕过」的说法，两种说法冲突 —— **只能实测一次**。

**结论：自动 HTTPS 要开**，然后老实测一遍。不通过就换给真证书的穿透方案。

⚠️ **绝不能用 UDP 隧道**。UDP 转发的是数据报，而 `wx.request` 走的是 TCP/HTTP，
两者根本不在一个频道上。

建隧道时另外两个字段：

- **远程端口**：自己填个五位数（比如 `23200`）。留空的话每次重启都会变，
  前端包里写死的地址就失效，又得重新构建。
- **访问密码**：留空。填了的话每个请求都得带密码，小程序那边没做这个处理。

> 参考：<https://doc.natfrp.com/frpc/auto-https.html>

#### 2.3 验证（关键一步）

一条命令搞定，别靠肉眼判断：

```bash
bash class-assistant/scripts/check-tunnel.sh frp-sea.com:23200
```

| 输出 | 含义 | 下一步 |
|---|---|---|
| `隧道通（HTTPS）` + `证书: 自签` | 隧道好了，卡在证书 | 照抄它给的 `VITE_API_BASE_URL`，构建后手机实测 |
| `隧道通（HTTPS）` + 受信任证书 | 最好情况 | 同上；域名白名单仍要「打开调试」才跳过 |
| `明文 HTTP 被 SakuraFrp 节点拦了` | 自动 HTTPS 还是禁用 | 去隧道设置里启用，重启后重跑 |
| `完全连不上` | 隧道没起 / 端口错 / 防火墙 | 逐个排查 |

⚠️ **每次重启隧道端口都可能变**（同一条隧道 10:51 是 `:46289`，11:06 变成 `:23200`）。
地址一变，前端包里写死的地址就失效，必须重新构建 —— 所以远程端口一定要自己填死。

不想用脚本也行，手机上**关掉 WiFi 用流量**，浏览器打开：

```
https://你拿到的地址:端口/api/teacher/home/overview
```

注意三件事：

- **是 `https://`**（自动 HTTPS 已开；写 `http://` 会被节点 501 拦掉）
- **端口不能漏** —— 端口是面板上那个五位数
- 路径是 `home` 不是 `homr`，完整路径 `/api/teacher/home/overview`

期望看到 `{"code":1002,...}`。
**这个"报错"就是成功** —— 说明服务活着、拦截器生效了。
浏览器会提示证书不受信任，点「继续访问」。

为什么必须用手机流量：连着 WiFi 时手机可能走的是内网路径，
验证不到「公网真的能访问」。只有走运营商网络才算数。

✅ **检查点 2 · 隧道（历史记录）**：手机流量下能看到 `{"code":1002}`。

> 这条路线最后卡在自签证书上——微信真机不给「继续访问」的选项，
> 所以实际上没走到这个检查点。留着是为了下次再试时不用重踩一遍。

> 如果这一步不通，先别管小程序。按顺序查：
> ① 隧道是否「运行中」② 地址端口有没有抄错 ③ TCP 隧道有没有被节点限制
> ④ 后端是否还在跑（回到第 1 步 curl 一次）⑤ 电脑防火墙是否拦了 8080
> ⑥ SakuraFrp 免费流量是否用完

### 第 3 步 · 前端指向你的 IP，重新构建

**为什么**：前端默认连 `localhost:8080`，而手机上的 `localhost` 指的是手机自己。
必须把地址换成电脑在热点里的 IP，打进包里。

```bash
cd class-assistant/frontend/uni-app/my-mp

cp .env.production.example .env.production    # 已有就不用复制
```

编辑 `.env.production`，改成你的地址：

```ini
VITE_API_BASE_URL=http://172.25.39.216:8080/api
```

三个容易写错的地方：

- **是 `http://` 不是 `https://`** —— 局域网没有证书，写 https 会 TLS 握手失败
- **端口不能省** —— 少了 `:8080` 会去连 80，直接拒绝
- **末尾的 `/api` 不能省** —— 它和后端接口前缀配套，漏了会全部 404

```bash
npm run build:mp-weixin
```

验证产物里真的写进去了：

```bash
grep -o "http://[0-9.]*:8080[^\"]*" dist/build/mp-weixin/api/request.js
```

应该看到 `http://172.25.39.216:8080/api`。**如果什么都没输出，说明环境变量没生效**，
检查改的是不是 `.env.production`（不是 `.env.development`），别往下走。

**「编译」这个词有两个意思，这是整条路线最坑的地方。**

| 你点的东西 | 它实际做了什么 |
|---|---|
| 微信开发者工具里的「编译」 | 只把**当前打开目录里已有的** wxml/wxss/js 重新打包一遍，**不会**跑 `npm run build` |
| `npm run build:mp-weixin` | 才真正把 `src/` 里的 `.vue` 编译成小程序代码 |

所以「改了前端代码、点了编译，界面没变化」是必然的 —— 工具压根没看你的 `.vue` 源文件。
正确顺序永远是：改 `src/` → `npm run build:mp-weixin` → 工具里点「编译」。

还有一个更隐蔽的坑：`dist/dev/mp-weixin` 和 `dist/build/mp-weixin` **目录同名**，
开发者工具顶部都显示 `mp-weixin`，肉眼完全分不出来。但两者内容天差地别：

| 目录 | 接口地址来自 | 实际指向 |
|---|---|---|
| `dist/dev/mp-weixin` | `.env.development` | `http://localhost:8080` ← 手机上必然连不上 |
| `dist/build/mp-weixin` | `.env.production` | 你的局域网 IP |

判断工具当前打开的是哪个，看这一个文件：

```bash
ls dist/build/mp-weixin/project.private.config.json
```

- **有** → 工具正打开 build 目录（正确）
- **没有** → 工具打开的是别处的目录，你改了也白改

`project.private.config.json` 只有开发者工具会创建，是「它打开过这个目录」的铁证。
同理，如果 `dist/dev/mp-weixin` 里有这个文件、`dist/build` 里没有，
说明你一直在预览 dev 包（连 localhost），而不是构建出来的正式包。

✅ **检查点 3**：`grep` 能打印出你的局域网地址，比如 `http://172.25.39.216:8080/api`。

### 第 5 步 · 真机预览，开调试模式

**为什么**：模拟器和真机是两回事。这一步验证「手机真的能连上」，
也是体验版能否用的最后一道关。

1. 开发者工具点「预览」
2. 手机微信扫码打开
3. **点右上角「···」→「打开调试」**
4. 小程序会重启，右下角出现一个绿色 `vConsole` 按钮

**第 3 步不能省，这是实测确认的。** 不开调试，微信会因为「明文 HTTP + 不是合法域名」
把请求全部拦掉，界面上只有一句「网络异常，请检查后端是否启动」——
和后端压根没开时的表现一模一样，很容易误判方向。开了调试立刻就好。

顺带澄清一个容易混的点：「打开调试」跳过的是**域名校验**，不是**证书校验**。
自签证书该拒还是拒（`errno: 600001`），开调试救不回来。
局域网直连压根没有证书，所以不受这条限制，这也是它比隧道省事的地方。

看数据是否正常显示。如果开了调试还是不通，别指望在手机上找到请求详情：
**微信内置的 vConsole 没有 Network 面板**，只有 `Log` / `System` / `WeChat` / `WXML` 四个标签。
红字在 `Log` 里，但拿不到完整 URL 和响应头。

真要看链路，从电脑侧反过来验：用 [`tools/connection-tester`](../tools/connection-tester/README.md)
直接探那个地址，它会告诉你断在 DNS / TCP / TLS / HTTP 的哪一段。

✅ **检查点 5**：手机上数据正常，vConsole 没有红色报错。

---

### 第 6 步 · 上传体验版，加体验成员

**为什么**：到这一步朋友才能用。他们不用装开发者工具，扫码就行。

#### 6.1 上传

开发者工具点「上传」，版本号填 `1.0.0`，备注写「首个体验版」。

#### 6.2 设为体验版

1. 打开 <https://mp.weixin.qq.com>，用管理员微信登录
2. 左侧「管理」→「版本管理」
3. 在「开发版本」里找到刚上传的，点右侧「···」→「选为体验版」

#### 6.3 加体验成员

1. 左侧「管理」→「成员管理」
2. 「体验成员」→ 添加，输入朋友的微信号

⚠️ **个人主体小程序最多 15 个体验成员**。够用了。

#### 6.4 发给朋友

体验版页面会生成一个二维码，**有效期 7 天**，过期重新生成即可。

把二维码发给朋友，并告诉他们：

> 扫码打开后，点右上角「···」→「打开调试」，然后重新进一次。

这一步朋友也必须做，否则微信会拦掉所有明文请求。**体验版同样支持打开调试**，
不用装开发者工具。

✅ **检查点 6**：朋友扫码后能看到真实数据。

---

### 第 7 步 · 以后每次改代码

形成了固定循环，每次都是这四句：

```bash
# 1. 改完代码后重新构建
cd class-assistant/frontend/uni-app/my-mp
npm run build:mp-weixin
```

2. 开发者工具里点「上传」，版本号加一（`1.0.1`、`1.0.2`…）
3. 后台「版本管理」→ 新版本「选为体验版」（**会覆盖旧的**）
4. 朋友重新扫体验版二维码即可

⚠️ **上传完不「选为体验版」的话，朋友看到的还是旧版**。这一步最容易忘。

## 让电脑别休眠

这是整套方案唯一需要额外注意的地方。Windows 默认会睡眠，
一睡后端就断了，朋友打开就是「加载失败」。

控制面板 → 电源选项 → 更改计划设置 → 把「使计算机进入睡眠状态」改成**从不**。

（只在你需要让朋友用的这段时间改，不用长期这样。）

## 常见故障

| 现象 | 原因 | 怎么办 |
|---|---|---|
| **`501 Not Implemented`（SakuraFrp 拦截页）** | 节点禁止明文 HTTP，**跟隧道类型无关**（TCP 隧道也拦） | 无解。改成「自动 HTTPS」只是换成自签证书，微信照样拒。走局域网直连，或换 cloudflared |
| **手机浏览器打不开 `IP:8080`** | 防火墙没放行 / 后端只听 `127.0.0.1` / 不在同一网段 | 加防火墙规则；确认后端监听 `0.0.0.0`；确认手机连的是同一个热点 |
| **昨天还能用，今天全挂，地址没动过** | 热点重连，电脑 IP 变了 | 重查 IP → 改 `.env.production` → 重新构建 |
| **浏览器能看 `{code:1002}`，小程序里却是「网络异常」** | 自签证书被微信真机拒之类 | 先确认手机已「打开调试」；仍不行说明自签过不了，换给真证书的穿透方案 |
| 小程序里「网络异常」，浏览器里同一个地址正常 | 没打开调试模式 | 右上角「···」→「打开调试」，小程序会重启 |
| 返回 404，页面是 JSON 的 `1004` | 路径拼错（如 `home` 写成 `homr`） | 核对完整路径 `/api/teacher/home/overview` |
| （隧道方案）手机浏览器打不开隧道地址 | 隧道没启动 / 地址端口抄错 | 看 SakuraFrp 面板是否「运行中」，核对端口 |
| （隧道方案）手机 WiFi 能开、流量打不开 | 走的是内网路径，不是真穿透 | 必须用流量验证；检查隧道是否真的建立了公网映射 |
| 开发者工具里转圈 | 后端没启动 | 回到第 1 步，curl 一下 |
| 提示 `url not in domain list` | 没开调试模式 | 右上角「···」→「打开调试」 |
| 提示 `request:fail` 且没别的信息 | 地址错了 / 端口不通 / 证书被拒 | 手机上用浏览器直接访问那个地址试试 |
| 朋友扫码提示「无权限」 | 不在体验成员名单里 | 后台「成员管理」加上 |
| 朋友看到的是旧界面 | 上传后没重新「选为体验版」 | 后台重新选一次 |
| 首页数据全是 0 / 未绑定班级 | 登录的不是李光老师 | 确认后端 `WX_MOCK=true`（默认就是） |
| 之前能用，突然全挂了 | 电脑休眠了 / 热点断了 / IP 变了 | 唤醒电脑，重连热点，按 2.0 第 3 步重查 IP |
| SakuraFrp 提示流量不足 | 免费版有日流量限制 | 控制台看用量，或换 cloudflared 临时顶一下 |

## 什么时候该升级到付费方案

出现下面任意一条，说明该花那 200 块了：

- 你需要**关电脑**（出门、上课、睡觉时也想让别人能用）
- 想让**不认识的人**用（15 个体验成员不够）
- 想让微信里搜得到（必须提审 → 必须备案 → 必须域名）
- **不想再让每个人点「打开调试」**（要正式 HTTPS，就得有备案域名 + 真证书）
- 隧道经常断，朋友抱怨打不开

升级路径见 [`deploy/README.md`](../deploy/README.md)，那边是完整的生产部署。

在那之前，**先把这个跑通、把功能玩明白**。功能没定下来就先去买服务器，
大概率是花钱买了个放在那里吃灰的机器。
