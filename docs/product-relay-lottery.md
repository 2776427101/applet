# 接龙与抽签 · 产品设计方案

> 面向「班级助手」班级群 / 课程群。所有尺寸沿用现有设计系统：
> 背景 `#F7EFE4`、卡片白 `#FFFFFF`、圆角 `28rpx`、主色 `#C5342B`、次要文字 `#9A9186`、分割线 `#F5EDE2`。

---

## 0. 三个前置判断（先定方向，再谈细节）

写方案之前必须先纠正三件事，否则后面做得再细也会跑偏。

### 判断一：群里现在只有老师在动手

`t_student` 没有 `user_id`，学生还没有账号（`docs/api-contract.md:2374`）。也就是说**群里只有老师能点**。

标准群聊产品的接龙是「发起 → 群里每个人自己接 → 满员」。照这个做，上线第一天你会看到一张 **0 人参与**的接龙卡，然后功能被判定为"没人用"。

所以 v1 必须给两条腿：

| 场景 | 谁动手 | 怎么做 |
|---|---|---|
| 老师登记（现在能跑） | 只有老师 | 发起人**代填**：卡片上直接"＋ 添加一条"，逐条录入学生姓名/学号 |
| 群成员自助（等学生账号） | 学生/家长 | 每人自己点，一人一条 |

接口和数据结构按"自助"设计，但 UI 上 v1 只开代填入口。等学生账号上线，把代填按钮换成"我要接龙"即可，**不用改后端**。

这条决定了接龙不是"报名工具"，v1 更像**在线点名册 / 登记表**。

### 判断二：抽签和抽奖是两个产品，别合并

- **抽签**（老师要的）：从名单里随机点人、随机分组。**不需要任何人参与**，老师点一下出结果。
- **抽奖**（活动用的）：大家先参与，再从参与者里抽。需要参与动机（点赞、口令）。

把两者塞进一个"抽签"里，配置项会变成十几个开关，老师看不懂。**v1 只做抽签（点名 + 分组），抽奖推到 v2。**

抽签天然不需要学生账号 —— 它抽的是 `t_student` 名单，这一点在当前状态下就能跑通，价值立刻兑现。

### 判断三：「＋」面板不需要"娱乐"分类

现在面板里只有 2 个功能（照片/视频、文件），加完也才 4 个。4 个东西分三类，每类一两个，标签比内容还占地方。

**功能数 ≤ 8 时不分类。** 分类是功能溢出后的补救，不是设计目标。真要分，也只分两类：`常用` 和 `更多`。

## 一、功能模块设计

### 1.1 接龙

#### 核心配置项

| 配置 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 接龙主题 | 文本 ≤ 30 字 | 必填 | 卡片标题，也进消息列表 |
| 说明 | 文本 ≤ 500 字 | 空 | 纯文本 + 换行，不做富文本 |
| **填写格式** | 单选 1-5 | 序号 | 见下表，这是接龙的核心配置 |
| 人数上限 | 数字 1-200 / 不限 | 不限 | 有值时卡片显示进度条 |
| 截止时间 | 日期时间 / 不限 | 不限 | 精确到分钟 |
| 是否需审核 | 开关 | 关 | 开启后提交为"待确认"，发起人通过才计数 |
| 结果展示 | 列表 / 表格 / 进度 | 列表 | 见下 |
| 允许参与者改自己的 | 开关 | 开 | 截止前可改 |
| 允许发起人改他人 | 开关 | 关 | 默认关：改别人的记录最容易产生纠纷 |
| 是否置顶卡片 | 开关 | 关 | 置顶后卡片浮在聊天区顶部 |

**填写格式（核心）**

| 值 | 名称 | 输入控件 | 典型场景 | 额外配置 |
|---|---|---|---|---|
| 1 | 仅序号 | 无（一键） | 明天春游报名 | — |
| 2 | 数字 | 数字键盘 | 订几份午餐 | 最小值 / 最大值 |
| 3 | 手机号 | 数字键盘 11 位 | 家长联系方式 | 格式校验 |
| 4 | 短文本 | 单行 ≤ 20 字 | 姓名 + 班级 | 占位提示文案 |
| 5 | 单选 | 选项组 2-10 个 | 参加 / 不参加 / 待定 | 选项列表 |

**为什么只有这五种**：多选（"选两门课"）在接龙里的语义是"报名多件事"，那本质是**多个接龙**，不是多选。组合字段（姓名+手机号）留到 v2，用"字段模板"做，v1 用短文本 + 提示文案代替。

**结果展示**

- **列表**（默认）：`1. 张三` `2. 李四`，行高 88rpx，序号用等宽数字。
- **表格**：格式为数字/单选时可用，两列（姓名 / 值），列宽 40% / 60%。
- **进度**：只显示 `已报 12/30` + 进度条，不列名字。适合"报名人数多、不需要看谁"的场景。

#### 状态机

```
草稿 ──发布──> 进行中 ──┬── 到达截止时间 ──> 已截止
                        ├── 人数达上限 ────> 已满
                        └── 发起人结束 ────> 已结束
已截止/已满 ──发起人延长──> 进行中
任意状态 ──发起人取消──> 已取消（卡片变灰，不可再操作）
```

**已满和已截止是两个状态，不是一个。** 文案要分开：已满 → 「已满员，看看谁报了」；已截止 → 「已截止，共 23 人」。用户看到"已满"会想"那我能不能挤进去"，看到"已截止"不会。

#### 用户参与流程

```
① 发起
   ＋ → 接龙 → 填写页（上半：主题/说明；下半：格式/上限/截止）
   → 发布 → 聊天区插入卡片消息（type=5）+ 自动聚焦到卡片

② 卡片展示
   卡片上直接显示：标题 / 已报 N/M / 截止时间 / 主按钮
   ★ 关键：格式为「仅序号」时，卡片按钮 = 「我要接龙」，点一下即完成，不进页面

③ 参与填写
   格式 2-5 → 点卡片进详情页 → 底部表单 → 提交
   代填模式 → 详情页右上角「＋ 添加」→ 选学生 / 手输 → 连续录入（不清空页面，方便连打）

④ 状态反馈
   成功：toast「已接龙，第 13 位」+ 卡片立即变「已参与」
   我的条目：详情页顶部固定一条「我的填写：3 份 · 修改」，不用在长列表里找自己
```

**第 ② 步的"一键接龙"是这个功能的价值所在。** 报名类接龙 90% 是"我就是要去"，让用户点两下（进页面 → 点提交）纯属浪费。只有真的需要填内容时才进页面。

#### 一个容易被忽略的设计：不要产生"参与消息"

每有人接龙就往群里发一条「张三 参与了接龙」——3 个人还好，30 个人就是刷屏，会把真正的聊天挤没。

**做法**：接龙只在卡片上变数字，不产生新消息。卡片本身是那条消息，它自己会更新。

### 1.2 抽签

#### 三种模式

| 模式 | 老师要解决什么 | 输入 | 输出 |
|---|---|---|---|
| **随机点名** | 上课提问点谁 | 名单 + 抽 N 人 | N 个名字 |
| **随机分组** | 分组讨论怎么分 | 名单 + 分 k 组 | k 组名单 |
| **抽奖**（v2） | 活动抽奖 | 参与者 + 奖项 | 中奖者 |

v1 只做前两个。它们共同点：**不需要别人参与，发起人一个人就能完成**。

#### 核心配置项

| 配置 | 适用 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| 抽签类型 | 全部 | 单选 | 点名 | 点名 / 分组 |
| 名单来源 | 全部 | 单选 | 当前班学生 | 当前班学生 / 手动勾选 / 导入名单 |
| 抽取人数 | 点名 | 数字 1-N | 1 | 不超过名单人数 |
| 分组方式 | 分组 | 按组数 / 按每组人数 | 按组数 | 二选一，另一个自动算 |
| 组数 | 分组 | 数字 2-20 | 4 | 人数除不尽时最后一组少人 |
| 是否去重 | 点名 | 开关 | 开 | 开：已抽过的人不再进入下一轮（可"重置"） |
| 是否公开结果 | 全部 | 单选 | 群内公开 | 群内公开 / 仅发起人可见 |
| 动画时长 | 全部 | 固定 | 1.2s | 不给配置，配置它没有意义 |

**"中奖概率"不放进 v1。** 概率/权重是抽奖的东西，抽签要的是"每个人机会一样"。给抽签加权重，等于给老师一个"内定"工具，一旦被学生发现就是信任问题。

如果将来真要做（比如"上次没被点到的加权"），做成**规则**而不是**手动权重**：`优先抽最近 N 次没被抽到的人`。规则可解释，手动权重不可解释。

#### 参与流程（点名模式）

```
① 发起：＋ → 抽签 → 选"随机点名" → 选名单 → 选人数 → 发布
② 卡片：显示「随机点名 · 未开始」「名单 57 人，抽 3 人」
③ 抽：发起人点卡片按钮「开始抽」→ 卡片内名字快速滚动 1.2s → 定格
④ 结果：卡片展开显示 3 个名字（大字 + 主色）+「再抽一次」+「查看名单」
⑤ 记录：抽过的结果存下来，可翻看"这节课点过谁"
```

**动画只在卡片内做，不做全屏遮罩。** 全屏遮罩要处理"点哪里关闭""返回键怎么办"，成本高、收益低；卡片内滚动同样有仪式感，还能让旁边的人看到抽的是哪张卡。

#### 分组模式的结果展示

分组不用动画（分完要看的是名单，不是过程）。直接出一张分组表：

```
第 1 组（5 人）   第 2 组（5 人）
张三  李四        王五  赵六
...

[ 重新分组 ]  [ 复制结果 ]
```

`复制结果` 复制成纯文本（组名 + 换行 + 名字），方便老师粘到别处。

## 二、「＋」面板界面优化

### 现状

```
┌─────────────────────────────────┐
│  ▣        ▣                     │
│ 照片/视频  文件                  │
└─────────────────────────────────┘
```
左对齐、每项 150rpx、只有 2 项。

### 目标布局

**4 列宫格，一行 4 个，最多两行。**

```
┌───────────────────────────────────────┐
│   ▣       ▣       ▣       ▣           │
│ 照片/视频  文件    接龙    抽签         │
│                                       │
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  │   ← 仅在功能 > 4 时出现
│   ▣       ▣                           │
│  位置    投票                          │
└───────────────────────────────────────┘
```

具体规格：

| 元素 | 值 |
|---|---|
| 面板 padding | `32rpx 24rpx 40rpx` |
| 每项宽度 | `25%`（4 列），`flex-wrap: wrap` |
| 图标 | `96rpx` 圆角 `28rpx`，底色 `#F3E9DC`，线性图标 40rpx |
| 文字 | `22rpx`，`#6B6157`，`margin-top: 14rpx` |
| 行间距 | `28rpx`（第二行 `margin-top: 28rpx`） |
| 分组分隔 | `1rpx` 虚线 `#F0E6D8`，上下各 `24rpx` |

**为什么是 4 列而不是 3 列**：3 列每项 234rpx，图标和文字之间会有大片空白，看起来像"没排满"；4 列正好和微信/QQ 的手感一致，用户不用重新学。

**为什么不做分类 Tab / 左右滑动**：功能只有 4-6 个，滑动会让用户不知道右边还有内容（这是移动端最经典的发现性问题）。**分类是功能溢出后的补救**——等真到 12 个功能再做，那时用两行 + 分隔线，仍然不需要 Tab。

### 交互

| 需求 | v1 是否做 | 理由 |
|---|---|---|
| 自定义排序 | ❌ | 只有 4 个功能，排序收益接近 0，但要做拖拽 + 保存 + 冲突处理 |
| 长按拖拽 | ❌ | 同上。且面板是"每次都要重新打开"的临时界面，拖拽需要教学 |
| 记住最近使用 | ❌ 已回退 | 原本做 ✅，上线后反馈"点谁谁跳到最前面"。面板靠肌肉记忆，位置一动手指就落错。详见工程笔记 §9.46 |
| 位置固定 | ✅ | 四个入口顺序永久固定：照片 / 文件 / 接龙 / 抽签 |
| 新功能红点 | ✅ | 红点在 **＋号上**，不在面板内的图标上——不打开面板就看不到的红点等于没有 |
| 红点消除 | — | 点开面板即消除（不是"用过才消除"，那会让用户为了消红点而乱点） |
| 新手引导 | ❌ 弹窗 | 用一次性气泡指向「接龙」图标，2 秒自动消失。不做全屏教学页 |

**为什么回退"记住最近使用"**：它把"少扫一眼"的收益换成了"每次都要重新定位"的成本。前者只发生一次，后者发生在每一次打开。要提升高频项的可达性，正确做法是在聊天页上给常驻入口，而不是在面板里换位置——换位置解决不了"要先打开面板"这一步。

### 图标

现有两个是自绘线性图标（`ic-media` / `ic-file`）。新增两个必须同风格：**40rpx 线宽 3rpx、圆头端点、单色 `#6B6157`**。

- **接龙**：三条横线，左侧带小圆点序号（`• ——` `• ——` `• ——`）
- **抽签**：一个签筒 + 一支斜出的签（不要用骰子，骰子会被理解成"游戏"）

## 三、聊天界面优化（消息气泡与卡片）

### 卡片结构

```
┌─────────────────────────────────────┐
│  ▣  接龙 · 进行中                    │  ← 16px 类型行，状态用色区分
│                                     │
│  春游报名                            │  ← 30rpx / 600
│  已报 12/30 · 周五 18:00 截止        │  ← 22rpx / #9A9186
│                                     │
│  ▓▓▓▓▓▓▓▓░░░░░░░░░░  40%            │  ← 4rpx 高进度条，仅有人数上限时
│                                     │
│  ┌───────────────────────────────┐  │
│  │           我要接龙             │  │  ← 88rpx 高，主色，圆角 20rpx
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

**尺寸约束（这是"不占屏"的关键）**

| 项 | 值 |
|---|---|
| 卡片宽度 | `容器宽 - 96rpx`（比气泡宽，因为它是功能性内容） |
| 卡片高度上限 | `320rpx`（约屏幕 1/4） |
| 超过上限 | 只留标题 + 一行元信息 + 按钮，其余进详情页 |
| 内边距 | `28rpx` |
| 卡片间距 | 上下 `20rpx` |

### 状态与按钮矩阵

| 状态 | 标签 | 标签色 | 主按钮 | 按钮态 |
|---|---|---|---|---|
| 进行中 · 未参与 | 接龙 · 进行中 | 主色 `#C5342B` | 我要接龙 | 实心主色 |
| 进行中 · 已参与 | 接龙 · 已参与 | 绿 `#3B6D11` | 修改我的填写 | 描边 |
| 已满 | 接龙 · 已满员 | 灰 `#9A9186` | 查看名单 | 描边灰 |
| 已截止 | 接龙 · 已截止 | 灰 | 查看名单 | 描边灰 |
| 已结束 | 接龙 · 已结束 | 灰 | 查看结果 | 描边灰 |
| 已取消 | 接龙 · 已取消 | 灰 | （无按钮） | 整卡置灰 |

**"已参与"必须变绿并改文案。** 用户回来看到"我要接龙"会怀疑自己到底报没报，这是接龙类功能最常见的困惑。

### 抽签卡片

```
未开始                     已开奖
┌───────────────────┐    ┌───────────────────┐
│ ▣ 抽签 · 未开始    │    │ ▣ 抽签 · 已开奖    │
│ 随机点名           │    │ 随机点名           │
│ 名单 57 人 · 抽 3  │    │  张三  李四  王五  │
│ [   开始抽   ]     │    │ [ 再抽一次 ] [名单]│
└───────────────────┘    └───────────────────┘
```

中签名字用 `34rpx / 600 / 主色`，横向排，超过 3 个折行并显示「等 5 人」。

### 让卡片不刷屏的四条规则

1. **接龙/抽签不产生"参与消息"**。卡片自己更新，不进消息流。
2. **同一张卡片只发一条消息**。编辑接龙配置不重新发消息，只更新卡片。
3. **卡片高度硬上限 320rpx**，超出折叠。这条是防止"接龙说明写了 500 字"把整屏吃掉。
4. **系统提示合并**。同一张卡片的多次状态变化（如 12→13→14）不各发一条，只改卡片上的数字。

### 让卡片更容易被点

- **整张卡片可点**，不只是按钮。但按钮仍然要显眼（实心、88rpx 高）。
- **卡片顶部加 2rpx 左侧色条**（进行中 = 主色，已结束 = 灰）。一屏里有三张卡片时，色条让人一眼分辨哪张还活着。
- **卡片出现在消息流时自动滚动到位**，并短暂高亮 300ms。

## 四、异常情况与边界处理

### 接龙

| # | 场景 | 现在会发生什么 | 预案 |
|---|---|---|---|
| 1 | 已满员，仍有人点提交 | 轮询 3s 有延迟，前端按钮还是可点的 | 提交时后端校验 → 返回 `4101 已满员`，前端弹「刚好满了，第 31 位是李四」，同时把卡片刷成已满。**不要只报"提交失败"** |
| 2 | 截止时间到了但页面没刷新 | 按钮仍可点 | 前端起一个本地定时器，每秒比对 deadline，到点自动禁用 + 改文案；后端仍然校验（前端只负责体验，不负责正确性） |
| 3 | 网络延迟，用户连点两次 | 产生两条记录 | 幂等键 `clientMsgId` + 唯一索引 `UNIQUE(relay_id, user_id)`；重复提交返回已有记录，**不报错**（报错会让用户以为没成功，继续点） |
| 4 | 两人同时抢最后一个名额 | 可能都成功 | 后端用 `UPDATE ... WHERE count < max` 原子更新，受影响行数 0 则判定已满 |
| 5 | 参与者改了昵称 | 列表里名字变了 | 接龙条目存**昵称快照**。名单是历史记录，不该因为改名而变 |
| 6 | 发起人退群 / 班级归档 | 卡片永久停在"进行中" | 群解散或班级归档时，后端把该群所有进行中的接龙置为「已结束」；卡片显示「该群已解散」 |
| 7 | 代填时重复录入同一个人 | 同一人两条 | 代填也走 `UNIQUE(relay_id, user_id)`（按 studentId 而不是 userId）；重复时提示「张三 已在第 3 位」 |
| 8 | 说明文字写了 500 字 | 卡片撑满整屏 | 卡片内说明最多显示 2 行 + 省略号，完整内容进详情页 |

### 抽签

| # | 场景 | 预案 |
|---|---|---|
| 9 | 名单人数 < 抽取人数 | 发布时就拦：`抽取人数不能超过名单人数`；编辑名单后人数变少，保存时再校验一次 |
| 10 | 去重模式下人都抽完了 | 按钮变「名单已抽完」+ 提供「重置记录」。不要静默失败 |
| 11 | 两人同时点「开始抽」 | 乐观锁 `version`；后到者返回「已开奖」并直接展示结果，不报错 |
| 12 | 分组人数除不尽 | 最后一组少人，并在结果里注明「第 4 组 4 人（余数）」 |
| 13 | 弱网下动画卡住 | 动画固定 1.2s，`setTimeout` 兜底 1.5s 强制出结果；动画期间按钮禁用，防止连点 |
| 14 | 抽签结果要"仅发起人可见" | 结果存后端，前端按角色决定是否下发；**不能靠前端隐藏**——群里任何人抓包都能看到 |
| 15 | 名单里有人在抽签后转班/退学 | 发布时存名单快照（studentId 数组）。开奖用快照，结果里标注「1 人已不在本班」 |

### 通用

| # | 场景 | 预案 |
|---|---|---|
| 16 | 老版本客户端收到 type=5/6 消息 | 消息 `content` 存降级文本 `[接龙] 春游报名`，老版本按普通文本气泡显示，不会白屏 |
| 17 | 群被禁言 | ＋ 面板里接龙/抽签按钮置灰，点击提示「你已被禁言」 |
| 18 | 卡片消息被撤回 | 卡片随消息一起消失；后端同时把接龙/抽签置为「已取消」 |

### 消息类型扩展

现有 `t_container_message.type`：`1 文本 / 2 图片 / 3 视频 / 4 文件`。

新增：

| type | 含义 | `content` 存什么 |
|---|---|---|
| 5 | 接龙卡片 | 降级文本 `[接龙] 春游报名`；`refId` = relay_id（新字段） |

## 六、分期建议

| 期 | 内容 | 为什么这个顺序 |
|---|---|---|
| **MVP** | 接龙（序号格式 + 人数上限 + 代填）、抽签（点名，当前班名单）、＋ 面板 4 列 | 不依赖学生账号，做完立刻能用。抽签是老师单人就能获得价值的入口 |
| v1.1 | 接龙五种格式、截止时间、结果三种展示、抽签分组 | 格式和展示是"用起来之后才知道要什么"的东西 |
| v1.2 | 学生自助接龙、置顶、审核 | 依赖学生账号上线 |
| v2 | 抽奖（参与制、概率、定时开奖）、投票 | 需要参与动机，属于另一个产品 |

**一句话总结**：先做**老师一个人能玩转**的部分（代填接龙 + 随机点名），把"依赖学生账号"的自助流程留到账号体系上线之后。这样这两个功能不会因为"没人参与"而变成废功能。
